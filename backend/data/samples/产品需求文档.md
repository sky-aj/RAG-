# 产品需求文档 v4.2

本文档描述对外接口的限流策略与配额管理，适用于所有开放平台租户。

## 1. 限流策略

### 1.1 默认额度

对外接口按租户维度限流，默认额度为每分钟 600 次请求、并发 20。
额度以滑动窗口统计，超出后返回 429 并附 Retry-After 响应头，提示最早可重试的秒数。

### 1.2 突发流量

突发流量允许短暂超出配额，上限为默认值的 1.5 倍，持续不超过 10 秒。
超出突发额度后立即拒绝，不做排队。

| 场景 | 限额 | 说明 |
| --- | --- | --- |
| 默认 | 600 次/分钟 | 所有租户 |
| 突发 | 900 次/分钟 | 持续不超过 10 秒 |
| 企业版 | 3000 次/分钟 | 需申请 |

## 2. 提额申请

企业版租户可在控制台自助申请提额，审批通过后额度在下一次心跳（最长 60 秒）内生效，无需重启服务。

```python
def check_quota(tenant_id: str, window_seconds: int = 60) -> dict:
    """返回租户当前窗口的剩余额度。"""
    used = redis.incr(f"quota:{tenant_id}")
    if used == 1:
        redis.expire(f"quota:{tenant_id}", window_seconds)
    return {"used": used, "limit": 600, "remaining": max(0, 600 - used)}
```

## 3. 常见排查

同一 API Key 被多个环境共用，是 429 报告频繁出现的常见原因，建议按环境拆分 Key。

> 滑动窗口意味着额度随请求时间推移连续释放，而不是整点重置。
